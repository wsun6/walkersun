Coding standards exist for a reason, and it can be annoying to implement at first. This was the case for me when I first started, as I wouldn't properly use spaces when using math operators or I would write extremely long single lines. This was only acceptable when doing simple practice exercises, but as the projects became more complicated, the code became progressively more tedious to read. It was then that I understood the importance of coding standards and how much time it saves compared to the time it takes to implement. Not only does it make your code a lot easier to look at and understand, it helps the programmer think deeper about what they're doing. It takes a certain level of knowledge to format the code in such a way that anyone can quickly understand, which can then provide more learning opportunities. I had to learn more about each language I was using when conforming to coding standards, which made me learn more about the language and then more about software engineering.

Using ESLint with VSCode felt tedious at first, because there were a lot of errors that wouldn't affect the code itself, and fixing it sometimes broke something. The coding standards that I used were mostly personal preference, so following ESLint was rather new. Getting rid of errors turned out to be rather simple however, as ESLint comes with a built in function that fixes all the small syntax errors that would be annoying to change. Learning to use the --fix command turned out to be very convenient as I could watch as things such as double quotes, spaces between parentheses, and leading commas would get automatically cleared. When doing the VSCode exercises, I often ran the debugger to see if my code works as intended before using ESLint. This led to some confusion as the program would run fine, but ESLint would throw errors that I didn't know about. These errors caused a lot more problems than the typical coding standards, as I would then need to fix them properly, leading to the previously mentioned learning opportunities. I think that using ESLint has been a good experience for me, as these exercises got me more familiar with software engineering. It is important to have coding standards, as following ESLint has made my code look a lot nicer, and I'm sure that I would have a much easier time if I were to look back at what I did.
